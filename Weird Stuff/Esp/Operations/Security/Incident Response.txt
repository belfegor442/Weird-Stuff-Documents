WEIRD STUFF
INCIDENT RESPONSE

Version: 1.0
Status: IN FORCE
Effective Date: September 12, 2026
Owner: Weird Stuff
Classification: RESTRICTED

1. PURPOSE

This procedure defines the baseline response to security and major operational incidents.

2. INCIDENT TYPES

An incident may affect:

* Confidentiality.
* Integrity.
* Availability.
* Authenticity.
* User security.
* Organizational infrastructure.

3. RESPONSE ORDER

1. DETECT
2. CONTAIN
3. PROTECT
4. RECOVER
5. INVESTIGATE
6. CORRECT
7. PREVENT RECURRENCE

4. MANDATORY ACTIONS

[MANDATORY]
Significant incidents must be reported to the appropriate responsible person as soon as reasonably possible.

[MANDATORY]
Known compromised credentials must be secured.

[MANDATORY]
Evidence relevant to understanding the incident should not be intentionally destroyed.

[MANDATORY]
Recovery actions must not knowingly create additional unacceptable security risk.

5. POST-INCIDENT

[RECOMMENDED]
Significant incidents should receive a post-incident review.

The review should identify:

* Root or contributing causes.
* Impact.
* Actions taken.
* Recovery status.
* Corrective actions.
* Preventive actions.

[PENDING]
Formal incident severity matrix.
[PENDING]
Formal incident reporting channel.
[PENDING]
Evidence-retention requirements.
