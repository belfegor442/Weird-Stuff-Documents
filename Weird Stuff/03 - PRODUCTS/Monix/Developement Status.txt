6. RENDERING STATUS
===================

Monix uses a specialized rendering architecture designed around
Vulkan and shader-based processing.

Current architectural areas include:

* Vulkan rendering.
* Dynamic Rendering.
* SPIR-V.
* Slang shaders.
* .slangp presets.
* Multi-pass processing.
* Runtime shader management.
* Shader cache.
* External texture handling.
* Feedback and pass-resource management.

[MANDATORY]

Rendering changes must preserve application stability and must not
knowingly compromise unrelated system functionality.

============================================================
7. SHADER STATUS
================

Shader processing is an active development area.

Current shader-related functionality may include:

* Slang compilation.
* SPIR-V generation.
* Shader presets.
* Multi-pass pipelines.
* Dependency handling.
* Shader caching.
* Runtime loading.
* Validation.

[MANDATORY]

Shader resources must be validated before being treated as valid
runtime resources.

[MANDATORY]

A shader failure must not be treated as a successful initialization.

[RECOMMENDED]

Shader changes should be tested independently before being
included in a major product release.

============================================================
8. SHADER CACHE STATUS
======================

The shader cache is intended to minimize unnecessary recompilation.

Relevant cache information may include:

* Source content.
* Shader stage.
* Language.
* Compiler version.
* Dependency hashes.
* Manifest information.
* Integrity data.

[MANDATORY]

Cache entries must be invalidated when relevant source,
dependency, compiler, or compatibility information changes.

[MANDATORY]

Invalid or corrupted cache data must not be blindly trusted.

[RECOMMENDED]

Cache size should be controlled through an eviction strategy.

12. SCRAM STATUS
================

SCRAM is an emergency-response subsystem.

Current modes:

TEST
REAL

TEST mode is intended for controlled testing.

REAL mode is intended for actual response actions.

[MANDATORY]

TEST mode must not intentionally execute actions exclusive to
REAL mode.

[MANDATORY]

The currently active SCRAM mode must be identifiable by the User.
